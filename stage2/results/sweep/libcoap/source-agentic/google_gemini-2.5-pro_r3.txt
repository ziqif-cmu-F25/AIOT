HYPOTHESIS: I have a solid vulnerability in `coap_opt_length`. I will now prepare the final report. The vulnerability is an out-of-bounds read in `coap_opt_length` when parsing a malformed CoAP option. This can lead to an inflated length value being returned. While I haven't traced this to a specific write-what-where primitive, many parts of the code use this function before a `memcpy`, which is a dangerous pattern. For example, `coap_block.c:952`: `memcpy(lg_xmit->b.b2.rtag, coap_opt_value(opt), coap_opt_length(opt));`. An attacker could leverage this to cause a denial of service (crash) or potentially information disclosure by reading adjacent memory into an option's value which is then processed or returned.
