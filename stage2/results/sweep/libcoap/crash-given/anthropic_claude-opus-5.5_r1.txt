**Ranked root-cause candidates**

The ASan report shows a **WRITE of size 300** into the static global `coap_resolve_address_info.addrstr`, which is 256 bytes. The write starts at the beginning of the buffer, so it runs 44 bytes past the end. Only one place in that function writes a variable length into `addrstr`: the `memcpy` at line 538. The rest of the source shows how a 300-byte host reaches it.

**How the input gets there**
- A Uri-Host option is capped at 255 bytes by `coap_pdu_parse_opt_base` (line 1188).
- A Proxy-Uri option may be up to 1034 bytes (line 1256).
- In the proxy path, `coap_proxy_get_session` calls `coap_split_proxy_uri()` on the Proxy-Uri. That fills `uri.host` with a pointer and length into the option, with no length limit (coap_uri.c line 202).
- `coap_proxy_get_ongoing_session` then passes `&server_use->uri.host` to `coap_resolve_address_info()` (coap_proxy.c line 420).
- That function copies `address->length` bytes into `addrstr[256]` without checking the length.
