**Root cause:** in the WRITE_AND_READ_REGISTERS (FC 0x17) handler, the bounds check meant to reject a negative write offset tests the read offset a second time. A negative `mapping_address_write` therefore passes, and line 980 writes before the start of `tab_registers`.

**How the crash happens**

- The crash is a WRITE in `modbus_reply` at line 980: `mb_mapping->tab_registers[i] = ...`.
- That line is in the write loop, which starts at `i = mapping_address_write`.
- Line 953 computes `mapping_address_write = address_write - mb_mapping->start_registers`.
- `address_write` is a 16-bit value taken from the request. The test server uses a non-zero `start_registers`, so any `address_write` below `start_registers` makes `mapping_address_write` negative.
- The address check at lines 962–965 is:
  ```c
  mapping_address < 0 ||
  (mapping_address + nb) > nb_registers ||
  mapping_address < 0 ||                          /* line 964: duplicate */
  (mapping_address_write + nb_write) > nb_registers
  ```
- The write offset is only checked against the upper bound (line 965). Nothing checks that it is non-negative.
- So a negative `mapping_address_write` passes, and line 980 writes to `tab_registers[negative]`. The write lands before the heap allocation; the faulting address `0x505ffffffec8` is consistent with a negative index from the register array.
- Every other handler (e.g. lines 800, 825, 853, 882, 930) checks its own `mapping_address < 0`. This is clearly a copy-paste slip.
