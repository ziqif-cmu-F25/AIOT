**Diagnosis**

The crash is a SEGV caused by a WRITE at `modbus.c:980`, inside `modbus_reply`. That line is in the `MODBUS_FC_WRITE_AND_READ_REGISTERS` (0x17) handler:

```c
mb_mapping->tab_registers[i] = (req[offset + j] << 8) + req[offset + j + 1];
```

Here `i` starts at `mapping_address_write`, which is computed as `address_write - mb_mapping->start_registers` (line 953).

The fault address is `0x505ffffffec8`. It sits just below a heap region around `0x5060...`. This fits a negative index into `tab_registers`, which is a write before the start of the buffer, not past its end.

The guard at lines 962–965 checks:

```c
} else if (mapping_address < 0 ||
           (mapping_address + nb) > mb_mapping->nb_registers ||
           mapping_address < 0 ||                                   /* line 964: duplicate! */
           (mapping_address_write + nb_write) > mb_mapping->nb_registers) {
```

Line 964 repeats `mapping_address < 0` instead of checking `mapping_address_write < 0`. So the write address is never checked for a lower bound. Only its upper bound (`mapping_address_write + nb_write <= nb_registers`) is checked, and a negative value always passes that.

The attack works when the mapping has `start_registers > 0`. A crafted FC 0x17 request can then use:
- a valid read address, and
- a write address below `start_registers`.

The negative `mapping_address_write` passes every check, and the loop writes attacker-controlled 16-bit values before `tab_registers` on the heap.
