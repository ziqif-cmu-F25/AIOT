1. **Out-of-bounds write in `modbus_reply` for function code 23 (MODBUS_FC_WRITE_AND_READ_REGISTERS)**
   - **Location**: {"file": "libmodbus/src/modbus.c", "function": "modbus_reply", "line": 947}
   - **Vulnerability class**: buffer-overflow
   - **Hypothesis**: When processing a MODBUS_FC_WRITE_AND_READ_REGISTERS request, the code writes to `mb_mapping->tab_registers` without properly validating the `mapping_address_write` index. An attacker can craft a request with a large `address_write` value that causes an out-of-bounds write.

     - Lines 964-965: The check `(mapping_address_write + nb_write) > mb_mapping->nb_registers` is incorrect because it uses `mapping_address` instead of `mapping_address_write`.
     - Line 980: `mb_mapping->tab_registers[i] = ...` where `i` can be out-of-bounds.
   - **Confidence**: 0.9

2. **Out-of-bounds read in `_modbus_receive_msg` during message parsing**
   - **Location**: {"file": "libmodbus/src/modbus.c", "function": "_modbus_receive_msg", "line": 450}
   - **Vulnerability class**: oob-read
   - **Hypothesis**: The function `compute_data_length_after_meta` uses untrusted data from the message to compute the length to read. If the computed length is too large, it might cause an out-of-bounds read when reading from the socket.
   - **Evidence**: 
     - Line 450: `length_to_read = compute_data_length_after_meta(ctx, msg, msg_type);`
     - Line 451: Checks if `(msg_length + length_to_read) > (int)ctx->backend->max_adu_length`, but only after using the value to read.
   - **Confidence**: 0.7

3. **Integer overflow in `compute_response_length_from_request`**
   - **Location**: {"file": "libmodbus/src/modbus.c", "function": "compute_response_length_from_request", "line": 146}
   - **Vulnerability class**: integer-overflow
   - **Hypothesis**: For function codes like MODBUS_FC_READ_HOLDING_REGISTERS, the number of registers is taken from the request and multiplied by 2. If the value is large enough, it can cause an integer overflow, leading to a buffer overflow later.
   - **Evidence**: 
     - Line 146: `length = 2 + 2 * (req[offset + 3] << 8 | req[offset + 4]);`
     - If `nb` (from the request) is 0x8000 or more, then `2 * nb` overflows.
   - **Confidence**: 0.6
