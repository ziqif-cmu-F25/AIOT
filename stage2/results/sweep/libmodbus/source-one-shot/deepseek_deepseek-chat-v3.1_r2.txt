However, if `address_write` is very large (e.g., larger than `mb_mapping->start_registers + mb_mapping->nb_registers`), then `mapping_address_write` becomes a large positive number that exceeds the size of the `tab_registers` array. This leads to an out-of-bounds write when the code writes to `mb_mapping->tab_registers[i]` at lines 980-982.

Similarly, the same pattern exists in other write operations (like `MODBUS_FC_WRITE_MULTIPLE_COILS` and `MODBUS_FC_WRITE_MULTIPLE_REGISTERS`), where the computed index might be out-of-bounds if the address is too large.

These vulnerabilities can be exploited by an attacker sending a malicious Modbus request with specially crafted addresses, causing a buffer overflow in the server's memory. This could lead to arbitrary code execution or a denial-of-service.
