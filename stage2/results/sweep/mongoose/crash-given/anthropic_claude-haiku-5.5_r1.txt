With the 3-byte input "ab\r", the function reads `buf[3]`, one byte past the end of the `malloc(3)` allocation. The fix is to validate each byte of the CRLF against the length before reading it. A stricter version also returns 0 ("need more data") rather than -1 when the buffer ends mid-CRLF, which is the correct behavior for a chunk-size line that arrives across multiple reads.
