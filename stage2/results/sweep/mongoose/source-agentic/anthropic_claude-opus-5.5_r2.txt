**Why the chunk length itself cannot cause an overflow.** `mg_str_to_num(..., sizeof(int))` caps the value at 0xFFFFFFFF. That value fits the 4-byte `int n`, so the store itself is in bounds. Values of 0x80000000 and above become negative and are rejected by `n < 0`. Line 1010 then compares the remaining length against `n` in signed `int`, so `i + n` never overflows. Once a full chunk has been accepted, both reads at line 1011 fall inside `len`. Because the second pass revisits chunks the first pass already validated, the `memmove` at line 1103 stays in bounds.
