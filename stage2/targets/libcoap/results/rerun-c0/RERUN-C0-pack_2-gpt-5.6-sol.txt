1. file: src/coap_address.c / function: coap_resolve_address_info() / approx line: 430
   bug class: out-of-bounds write / static-buffer overflow
   reasoning (quote the specific code line(s) involved):
   ```c
   static char addrstr[256];
   ...
   memset(addrstr, 0, sizeof(addrstr));
   if (address && address->length)
     memcpy(addrstr, address->s, address->length);
   ```
   `address->length` is not checked against `sizeof(addrstr)`. A proxy URI is permitted to be up to 1034 bytes, so its host can substantially exceed 256 bytes. The `memcpy()` then corrupts memory following the static buffer.
   how untrusted input reaches it (trace the data flow):
   Network Proxy-Uri option → `coap_proxy_get_session()` → `coap_split_proxy_uri(..., &server_use->uri)` sets `server_use->uri.host` to a slice of the option → `coap_proxy_get_ongoing_session()` → `coap_resolve_address_info(&server_use->uri.host, ...)` → unchecked `memcpy()` into `addrstr[256]`.
   triggering input characteristics:
   A request handled by a `*_STRIP` proxy configuration with a syntactically valid Proxy-Uri whose hostname exceeds 256 bytes, for example `coap://` followed by roughly 300 non-delimiter hostname bytes. The complete option must remain within the accepted 1034-byte Proxy-Uri limit.

4. file: src/coap_pdu.c / function: coap_pdu_parse_size() / approx line: 760
   bug class: out-of-bounds read
   reasoning (quote the specific code line(s) involved):
   ```c
   if (len < 13) {
     size = len;
     token_start = &data[2];
   }
   ...
   if (token_start) {
     if (tkl < COAP_TOKEN_EXT_1B_TKL) {
       size += tkl;
     } else if (tkl == COAP_TOKEN_EXT_1B_TKL) {
       size += token_start[0] + COAP_TOKEN_EXT_1B_BIAS + 1;
     } else if (tkl == COAP_TOKEN_EXT_2B_TKL) {
       size += ((uint16_t)token_start[0] << 8) + token_start[1] +
               COAP_TOKEN_EXT_2B_BIAS + 2;
     }
   }
   ```
   The function checks that the base reliable-transport header fits, but does not check that one or two extended-token-length bytes exist before reading them. With a two-byte TCP header, `token_start` can equal `data + length`.
   how untrusted input reaches it (trace the data flow):
   Bytes received over CoAP-over-TCP/TLS/WS framing → framing code calls `coap_pdu_parse_size(proto, data, available_length)` → attacker-controlled TKL nibble selects extended-token parsing → `token_start[0]` or `[1]` is read beyond the available bytes.
   triggering input characteristics:
   A truncated reliable-transport PDU containing only its base header, with the low nibble of the first byte set to `COAP_TOKEN_EXT_1B_TKL` or `COAP_TOKEN_EXT_2B_TKL`. For example, when the high length nibble is below 13 and only two bytes are available, `token_start == &data[2]`, so either extended case reads past the buffer.
